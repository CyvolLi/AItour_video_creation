# 小程序页面视觉对齐设计

## 目标

根据 `reference/UI_Image` 中的参考图，对以下 3 个小程序页面做视觉样式对齐：

- `miniprogram/pages/dialogue/dialogue`
- `miniprogram/pages/profile/profile`
- `miniprogram/pages/v_output/v_output`

本次只处理视觉层，不修改页面业务逻辑、数据流和接口行为。

## 范围

### 在范围内

- 页面外层背景、装饰层、留白、卡片圆角、阴影
- 顶部返回区、标题区、底部 dock 样式
- 聊天气泡、个人主页 tab、作品宫格、视频结果页按钮层次
- 为实现视觉对齐所需的少量 `wxml` 容器调整

### 不在范围内

- 首页 `miniprogram/pages/index/index`
- 社区广场 `miniprogram/pages/community/community`
- 模板选择 `miniprogram/pages/mode_select/mode_select`
- 页面逻辑 `js`、接口调用、字段结构、业务文案策略
- 新增公共组件或全局主题系统

## 页面设计

### 1. 对话页

- 保留现有消息列表和输入能力
- 强化顶部胶囊标题、返回按钮、浅色渐变背景和漂浮装饰
- 调整消息气泡的圆角、阴影、宽度和行间距
- 调整底部输入栏的圆角、边框感和按钮视觉，使其更接近参考图

### 2. 个人主页

- 增加顶部左右控制区，补齐左侧返回按钮
- 保留头像、昵称、ID、关注信息的结构，微调对齐、间距和字体层级
- 保留两层 tab 结构，增强通栏视觉和选中态
- 优化作品卡片圆角、边框感和底部 dock 的悬浮效果

### 3. 视频结果页

- 保留视频、文案、标签和发布流程
- 调整视频卡片、文案卡片、标签卡片和按钮容器的层级与留白
- 优化顶部返回按钮、叶片装饰和底部 dock
- 修正当前 `wxml` 中影响展示的文本/标签结构问题

## 实现策略

- 仅修改目标页面的局部 `wxml` / `wxss`
- 不抽离共享样式，避免扩大影响面
- 优先在现有 DOM 上补容器和装饰层，不重写业务结构

## 验证方式

- 使用 `git diff --check` 做静态检查
- 人工核对目标文件结构是否完整
- 由于仓库未配置自动化视觉回归，本次最终确认依赖微信开发者工具预览与参考图比对
