# 演示带货展示设计

## 目标

在不依赖微信小店接口、不改变发布请求和后端数据的前提下，为视频生成、视频详情和发布页面增加一套纯前端的演示带货 UI。所有商品均为演示数据，图片使用公开 HTTPS CDN 链接，不写入项目资源。

## 页面位置

- `pages/v_output`：视频播放内容下方、固定“发布作品”按钮上方增加一条横向商品条幅，展示一个主推商品。
- `pages/detail`：评论区标题下方、评论列表上方增加“视频同款好物”横向商品列表，展示三个商品。
- `pages/publish`：公开可见选项下增加“选择代言商品（演示）”开关。开启后展示一个算法选中的演示商品，但发布接口不接收该字段。

## 数据与算法

新建 `miniprogram/utils/demoProducts.js`，集中维护商品名称、短卖点、演示价格、标签和公开图片 URL。图片使用稳定的 `images.unsplash.com` 固定链接，例如咖啡、旅行用品、鞋子和食品图片；不使用随机 URL，不保存到本地。

模块导出：

- `DEMO_PRODUCTS`：不可变的演示商品数组。
- `getFeaturedProducts(limit)`：返回指定数量的浅拷贝列表，避免页面修改共享数组。
- `pickProduct(seed)`：将标题或视频 URL 转为稳定索引，同一内容在发布页重复进入时选择一致商品；没有 seed 时使用第一个商品。该算法只用于演示选择，不产生订单或网络请求。

## 交互与状态

- 商品条幅和商品列表点击时只显示“演示商品，暂不支持购买”，不调用 `wx.openEmbeddedMiniProgram`、`store-product` 或任何后端接口。
- 发布页开关默认为关闭；开启后显示商品预览和“仅用于演示”的标签。关闭后隐藏预览。
- 商品图片失败时显示统一的图片占位样式，文字信息仍保持可见。
- 所有文案明确“演示”属性，避免用户误认为真实商品、佣金或交易能力。

## 视觉

沿用现有页面的浅绿、浅蓝、白色面板、圆角和柔和阴影。商品条幅保持单行紧凑布局；详情页使用横向滚动卡片，避免挤压评论输入区；发布页使用现有 `option-pill` 形式，二元选择使用开关或勾选状态，不增加新的导航层。

## 网络图片限制

本地代码不保存任何图片文件。开发者工具本地调试可关闭域名校验；正式小程序需要在后台将 `images.unsplash.com` 加入图片/下载合法域名，否则应替换为已备案的公共 CDN 域名。

## 测试与验收

- Node 测试验证演示商品数据结构、稳定选择算法、数量限制和不修改共享数组。
- 页面测试验证三个页面包含演示商品绑定、发布开关只影响本地 UI 状态、点击不调用真实购买 API。
- 运行全部现有测试、JavaScript 语法检查和 JSON 解析。
- 在开发者工具和手机预览检查远程图片加载、横向滚动、底部按钮不遮挡以及发布请求 payload 未增加商品字段。
